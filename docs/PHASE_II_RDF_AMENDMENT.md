The earlier audit reported fragile bot-only initiation, not impossibility. Native LFG source is not fully in mirror: audit exact installed module/core. **New playtest evidence (owner-reported, not independently observed):** owner-led group has run dungeons through Gnomeregan, completed last night. Brannoc chain-pulls, generally navigates and tanks well; occasional owner kill-target marks redirect her when sidetracked. Gnomeregan traversal was mostly smooth with a few corrections. This substantially lowers uncertainty about current owner-led tactical competence; does NOT prove no-human queueing, independent navigation/target selection, every boss tactic or bot-only healing/recovery. Do not rewrite working combat systems. Preserve existing pace, kill-order, healer tether and human marks. Focus on identifying and replacing the small number of owner-dependent corrections.

## Native vertical slice
1. Individual eligible planner goal chooses specific dungeon ID(s) or a native random queue where supported. Item-specific gear source may motivate specific queue; quests, practice, fun, social activity may motivate random. Native random pool must be safe/supported; if not, use specific queue rather than silently changing random reward semantics.
2. Native queue owns role matching, proposal, acceptance, teleport/return. Opportunity layer owns optional intention, actual accepted commitment and evidence, not a duplicate queue. Repair installed bot-only queue/proposal path if necessary; audit existing LfgActions, group manager, native session handlers and progression restrictions. No human presence requirement for enrolled bot-only pilot. While queued, bot continues actual solo work until safe interrupt. Observe native response timeout; decline/expire safely.
3. Guard resource headroom and exact native group/roster/target authorization at admission; distinguish queued intent from active lease. MySQL/native state authoritative, SQLite read projections; no shadow mutations. Correlate actual queue/proposal/group/run and goal IDs. Keep protected core opt-in.
4. Native teleport and entry verification. Reuse established tank/assist/combat/navigation and role strategies; audit owner-dependent conditions in [CompanionLeadStrategy.cpp](https://github.com/Garblesnarff/hearthcore/blob/bfeed54e30cd39fba1bac9e1fc17dc168d41db06/mod-playerbots-companions/src/Ai/Base/Strategy/CompanionLeadStrategy.cpp), especially healer fallback, chain return and leader/master changes. Confirm actual leader progression when owner offline; leader doesn't stand idle waiting for a mark. If navigation is blocked, use bounded safe recovery, not blind teleport.
5. Build a correction trace: native mark source (human or AI), target ID, reason, encounter/map location, prior target and reason for switch, whether route/pull resumed. No raw chat. Owner manual marks always override when present. For bot-only group, select next valid pull/priority target based on actual route progression, engaged enemies, danger, healer range/mana and boss objectives; never pull just to match a mark. Reuse existing skull/kill-order logic rather than introducing LLM combat. Measure owner corrections per run against prior owner-led baseline, and autonomous stalls, unnecessary detours, wipes, objective completion. A human correction is a useful diagnostic, not a character failure or bad personality. Gnomeregan is a valuable regression fixture after easier pilot, not blanket support for every dungeon.
6. Actual boss/loot/quest outcome, safe recovery, leave/return through native LFG, resume previous objective or fresh optional rerun. Disable = stop new queue/admission, drain safely; owner recall and shifts at safe boundary. No automatic raid.

Acceptance: five willing compatible bots queue independently and native pop/accept/teleport while owner offline; one supported stock run completes with actual boss and loot events, safe exit and resumed tasks. Then repeat with role variation, no owner marks, leader loss, missed proposal, wipe, schedule/recall, restart and resource pressure. Compare owner-led regression; use Gnomeregan for navigation/mark test when roster is eligible. Manual travel fallback only if native approach genuinely unsupported after documented investigation and owner approval. Related #20, #11–#17, #19, #21–#24. Keep all live automation flags OFF until supervised native pilot. No feature deployment in this document.
